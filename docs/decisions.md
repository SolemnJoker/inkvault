# InkVault 决策记录 v1.0
配套文件：docs/requirements.md（需求层，US-01..US-13 / NFR-01..NFR-06）

## 0. 使用规则
- 每条决策必须包含：状态、关联需求、背景、决策、依据、影响范围、推翻条件。
- 实现过程中若与某条决策冲突，Agent 必须停止实现并在 PR/回复中提出，不得自行替换方案。
- 推翻一条决策需新增一条记录（D-13…）并保留旧记录，标注"被 D-xx 取代"，不删除历史。
- 里程碑提示词中的技术约束必须回指本文件编号（如"依据 D-05"）。

## 1. 决策记录

### D-01 主编辑路径禁用 WebView
- 状态：生效
- 关联需求：US-03、US-11、NFR-01、NFR-02
- 背景：低功耗是本项目立项动因；Web 渲染栈在移动端的启动开销、内存与持续功耗均高于原生文本渲染。
- 决策：正文编辑与阅读渲染走原生文本路径，禁止 WebView。唯一例外：Mermaid / KaTeX
  采用懒加载离屏渲染，且仅在可见时存活，离屏即销毁。
- 依据：功耗预算（NFR-01/NFR-02）无法在常驻 WebView 架构下稳定达成。
- 影响范围：M1 渲染、M2 编辑核心、M5 扩展。
- 推翻条件：若原生增量高亮在 1000 篇库 / 1MB 单文件上无法达到 NFR-02，且性能问题
  被证明源于自研解析而非实现质量，可重新评估"阅读视图用 WebView、编辑视图保持原生"的混合方案。

### D-02 不做插件系统
- 状态：生效
- 关联需求：US-03、US-09
- 背景：插件常驻是 Obsidian 移动端功耗与不稳定性的主要来源之一；本项目定位为轻量客户端。
- 决策：不实现插件加载、脚本注入、动态加载第三方代码；扩展仅限
  [[、![[、frontmatter、Mermaid、KaTeX（M5）。
- 依据：插件生态与低功耗目标存在结构性冲突，且引入审核与安全成本。
- 影响范围：全项目；架构中不预留插件宿主接口。
- 推翻条件：无。若确有需要，应作为新产品线讨论，不在本项目内演进。

### D-03 编辑核心用 UIKit UITextView 子类
- 状态：生效
- 关联需求：US-04、US-05、NFR-02
- 背景：声明式文本控件在长文本场景下每键性能与光标稳定性存在已知短板；vim 模式需要
  精确的按键拦截、选区与输入法交互控制。
- 决策：外壳用 SwiftUI（导航、列表、设置），编辑核心用 UITextView 子类承载自研 buffer；
  禁止用 SwiftUI TextEditor 承载正文。
- 依据：需要命令式控制按键、选区、undo 栈与 inputMode。
- 影响范围：M2、M3。
- 推翻条件：若 M2 实测表明 UITextView 子类无法满足击键 P95 < 8ms 或光标稳定性要求，
  可评估自研文本渲染层，但须先出性能对比数据。

### D-04 直接读写 vault，.obsidian 只读
- 状态：生效
- 关联需求：US-01、US-09、US-10
- 背景：Obsidian vault 即普通文件夹 + 纯文本 .md + 根目录 .obsidian 配置；整库复制会
  带来存储翻倍与双向同步歧义。
- 决策：通过 security-scoped bookmark 直接读写用户授权目录，不整库复制。.obsidian/
  严格只读，不写入、不删除；.trash/ 语义与 Obsidian 保持一致；默认隐藏内部目录。
- 依据：US-01 要求不产生副本，US-09 要求不污染桌面端配置。
- 影响范围：M1 文件树、M2 写盘、M4 忽略规则。
- 推翻条件：若 bookmark 在后台/重启后的可用性实测失败率过高（见 Spike A），
  可引入"App 沙盒内工作副本 + 显式回写"模式，但须重新评估 US-01 的验收标准。

### D-05 同步采用 Syncthing 内核按需拉起（手动/前台语义）
- 状态：生效
- 关联需求：US-07、US-08、US-12、NFR-03、NFR-04
- 背景：iOS 会冻结后台应用，第三方 Syncthing 客户端的共性痛点即后台同步不可靠；
  需求方已确认接受非实时、甚至手动同步。
- 决策：嵌入 Syncthing 内核，生命周期为"用户触发 → 启动 → 同步 → 停止"。
  不做后台同步；进入后台立即停止内核并取消全部网络活动。禁止 BGProcessingTask、
  后台 URLSession、常驻定时器与常驻文件监听。
- 依据：手动语义下"息屏零耗电"才可能稳定达成（NFR-03）；后台常驻与低功耗目标互斥。
- 影响范围：M0 Spike C、M4 全部。
- 推翻条件：若 Spike C 证明内嵌内核在按需生命周期下无法稳定完成跨网同步
  （连接成功率或资源释放不达标），则切换备选：(a) 固定地址直连；(b) 自研
  manifest 增量同步（需服务端）。切换须新增 D-13 并重估 M4 工作量。

### D-06 跨网采用自建私有中继
- 状态：生效（参数待定）
- 关联需求：US-07、US-12、NFR-04
- 背景：需求方自有公网服务器；跨网场景下公共中继池不可控，全局发现与 NAT 穿透
  会带来额外流量、耗时与不确定性。
- 决策：中继服务由用户自有公网服务器承载，客户端仅配置该私有中继地址，
  不使用任何公共中继池；关闭全局发现与 NAT 穿透，开启中继。
  端口、监听地址、限速、超时、访问控制等**不在文档与代码中硬编码或假定取值**，
  由 Spike C 实测后与需求方确认，并以配置项形式导入 App。
- 依据：跨网为必选场景；私有中继在可控性与功耗上均优于公共池。
- 影响范围：M0 Spike C、M4 配置与首次配置向导。
- 推翻条件：若实测显示经中继的连接成功率或耗时无法满足 US-07 的手动同步体验，
  则评估"直连优先 + 中继兜底"或改走服务端中转的自研同步方案。

### D-07 同步凭证与配置只存沙盒
- 状态：生效
- 关联需求：US-09、US-12
- 背景：Syncthing 的 config、证书、设备密钥若落入 vault，会被同步扩散并可能泄露。
- 决策：配置、证书、密钥一律存 App 沙盒，敏感项进 Keychain；绝不写入 vault。
- 依据：US-12 数据可控、US-09 不污染库。
- 影响范围：M4。
- 推翻条件：无。若因内核限制必须落盘到某目录，须保证该目录不在 vault 内。

### D-08 写入 vault 的同步产物默认关闭
- 状态：生效
- 关联需求：US-09
- 背景：部分同步能力（如忽略规则文件）可能需要在 vault 根落盘，与"不污染库"存在张力。
- 决策：默认采用 App 侧过滤 + .obsidian 只读保护；任何需写入 vault 的同步产物
  必须先在 UI 中说明用途并征得用户明确同意，且提供关闭路径。
- 依据：US-09 的验收标准是"不新增文件"，例外必须显式授权。
- 影响范围：M4 忽略规则实现。
- 推翻条件：若 App 侧过滤无法阻止某些文件被传输（如高频变动的 workspace 文件），
  可改为默认写入忽略文件，但须更新 US-09 验收标准并记录于本文件。

### D-09 写盘统一经 VaultWriter，并记录沙盒操作日志
- 状态：生效
- 关联需求：US-04、US-13
- 背景：版本历史（US-13）本期不实现，但未来实现不应改动调用方；同时需要一个
  低成本的变更溯源能力。
- 决策：所有对 vault 的写入统一经 VaultWriter（原子写 + 事务边界 + 可插拔 hook）；
  同时在 App 沙盒内维护 append-only 操作日志（时间、文件、变更类型、前后大小），
  不写入 vault。
- 依据：为 US-13 留接缝的成本极低，且对 US-04 的可靠性验证也有用。
- 影响范围：M2、未来 M6。
- 推翻条件：若操作日志在长期使用后出现体积或写入开销问题，可改为采样或滚动清理，
  但不得取消 hook 点。

### D-10 保存策略：防抖 + 原子写
- 状态：生效
- 关联需求：US-04、NFR-01
- 背景：击键即保存会持续触发磁盘写入与同步扫描，是功耗与冲突的主要来源之一。
- 决策：保存采用 800–2000ms 可配置防抖；写盘为"临时文件 + replace"原子替换，
  保留文件权限与创建时间；进入后台或挂起前必须完成挂起写入。
- 依据：US-04 要求不丢内容与不产生半写状态；防抖显著降低写入频率。
- 影响范围：M2。
- 推翻条件：若用户反馈防抖窗口内丢内容（如系统强杀时机），可缩短窗口或增加
  周期性强制落盘，但不得回到"每键写盘"。

### D-11 如实披露中继的元数据暴露面
- 状态：生效
- 关联需求：US-12
- 背景：中继只转发密文、不存数据，但会知晓连接设备的 IP 与设备 ID，并可观测流量规模。
- 决策：在"关于同步"等位置用用户能懂的一句话如实说明上述边界，
  不得宣称"无任何元数据暴露"或"完全匿名"。
- 依据：US-12 的验收标准要求说明可理解且准确。
- 影响范围：M4 UI 文案。
- 推翻条件：无（属于合规与诚信要求，不随技术变化而变）。

### D-12 版本历史本期完全不实现
- 状态：生效
- 关联需求：US-13
- 背景：需求方确认本期只用 Syncthing 能力；内核自带的文件版本控制会在同步目录内
  产生版本目录，与 US-09 存在张力，且与未来 Git 方案是取舍关系。
- 决策：不实现历史查看与回滚；**明确不开启任何内核/服务端自带的文件版本控制功能**，
  不在 vault 内创建版本目录、.git 或类似历史数据目录。仅保留 D-09 的两项零成本接缝。
  未来候选路径（快照式 / 本地 Git 式）仅记录于本文件，本期不实现、不默认开启。
- 依据：US-09 不污染库优先于 US-13（本期不在范围内）。
- 影响范围：M4（禁止项）、M6（未来）。
- 推翻条件：若冲突处理（US-08）在无历史能力下被证明不足以恢复误覆盖内容，
  可在 M6 引入候选路径，届时须重新评估 US-09 的边界。

## 3. 附录 B：已否决的备选方案
| 方案 | 否决原因 | 关联决策 |
|---|---|---|
| 自建键盘扩展实现输入法切换 | 独立沙盒进程、内存上限极低、需用户手动启用，且无法调用系统拼音输入法 | US-06 |
| 后台常驻同步 + BGProcessingTask | 与 NFR-03 互斥；iOS 冻结后台导致"看似连接却不同步" | D-05 |

| Git 作为本期同步方案 | 冲突 UI 与运维成本高；与 Syncthing 不应对同一 vault 同时生效 | D-12 |
| 开启内核文件版本控制换取回滚 | 在同步目录产生版本目录，与 US-09 冲突 | D-12 |
