# InkVault 需求基线 v1.0
范围：iPad 优先的 Markdown 笔记客户端，兼容 Obsidian vault，主打低功耗。
本文件只描述"要什么"，不含任何技术选型；技术决策见 decisions.md。

## 1. 用户故事

### US-01 打开现有库
作为已在桌面端使用 Obsidian 的用户，我希望在 iPad 上直接打开现有 vault 目录而不导入复制，
以便两端共用同一份笔记。
- Given 我已在桌面端有一个 vault 文件夹，When 我在 InkVault 中首次选择该目录并授权，
  Then App 直接读写该目录，不产生副本，且重启后无需重新选择即可打开。
- Given 我拥有多个 vault，When 我切换 vault，Then 文件树与内容随之切换，且各自的授权都保持有效。
- Given 授权已失效（目录被移动/权限丢失），When 我再次进入该 vault，
  Then App 明确提示并引导重新授权，不静默失败、不丢未保存内容。

### US-02 阅读渲染
作为读者，我希望看到标准 Markdown 及 Obsidian 常用扩展的正确渲染，以便无障碍阅读既有笔记。
- Given 一篇含标题、列表、表格、任务列表、删除线、代码块的笔记，When 我打开它，
  Then 上述元素按标准语义正确渲染。
- Given 笔记含 [[wikilink]]、![[embed]]、YAML frontmatter、相对路径图片，
  When 我阅读，Then 链接可跳转、嵌入内容可见、frontmatter 以属性表呈现、图片正确加载。
- Given 一篇超长笔记（含大量图片），When 我快速滚动，Then 不出现明显掉帧或空白滞留。

### US-03 低功耗
作为重度用户，我希望 App 静置与息屏时几乎不耗电、不发热，以便整天携带 iPad 而不影响续航。
- Given App 前台打开且我不输入，When 静置 10 分钟，Then 无网络请求、无明显 CPU 占用。
- Given 我完成一次同步并退出 App，When 息屏 1 小时，Then 无后台网络活动、无定时任务、无文件扫描。
- Given 我在编辑，When 连续输入 10 分钟，Then 设备不出现异常发热，能耗与同类原生笔记应用相当。

### US-04 可靠编辑
作为编辑者，我希望输入内容在短暂延迟后原子落盘、异常不丢内容，以便放心写作。
- Given 我在输入，When 停止输入约 1 秒，Then 内容被写入磁盘且不产生半写状态。
- Given 我编辑中 App 被系统终止，When 我重新打开该笔记，Then 最后一次已保存内容完整存在。
- Given 我进入后台，When 有未落盘的改动，Then 改动在挂起前完成写入。

### US-05 Vim 编辑
作为 vim 用户，我希望用熟悉的模式与命令编辑笔记，以便外接键盘时高效写作。
- Given 我处于 normal 模式，When 我按下 h/j/k/l/w/b/d/y/p 等命令，Then 光标与文本按 vim 语义变化。
- Given 我按 i/a/o 进入 insert，When 我输入文本，Then 文本正常插入且按键不被 vim 拦截。
- Given 我使用可视选择与计数前缀（如 3dd），When 执行命令，Then 作用范围与 vim 一致。
- Given 当前模式，When 我查看界面，Then 模式指示清晰可见。

### US-06 中文输入（最佳努力）
作为中文用户，我希望进入 insert 时能顺畅使用拼音、normal 时按键不被输入法干扰。
- Given 我进入 insert 模式，When 当前输入法不是中文，Then App 给出轻量提示或引导，
  并在能力允许时尝试切换；不承诺一定成功。
- Given 我处于 normal 模式并使用外接键盘，When 我按键，Then 按键由 App 处理，不触发输入法候选。
- Given 系统限制导致无法自动切换，When 我查看设置页，Then 有一段说明让我理解 App 做到哪一步。

### US-07 手动跨网同步
作为多设备用户，我希望在 App 内点一次"同步"即可完成与远端设备的双向同步（跨网络，
经我自建的中继服务器），以便不依赖后台常驻也能拿到最新笔记。
- Given 远端设备在线且可达，When 我点击"同步"，Then 双向变更被传输并展示结果报告。
- Given 远端不可达或网络异常，When 同步失败，Then 给出分类原因与可诊断信息，不静默丢改动。
- Given 我使用蜂窝网络，When 我发起同步，Then App 先请求确认再传输。
- Given 我退出到后台，When 同步未结束，Then App 停止同步并清理网络活动，不驻留后台。

### US-08 冲突可见
作为同步使用者，我希望冲突文件被明确标记并可对比选择保留版本，以便不丢失任何一端的修改。
- Given 同一文件在两端被修改，When 同步产生冲突，Then 冲突文件在列表中被标记且可识别。
- Given 存在冲突文件，When 我打开它，Then 我能对比两端内容并选择保留本地、保留远端或都保留。
- Given 冲突未处理，When 我继续编辑，Then App 不覆盖任一版本，且提示我处理。

### US-09 不污染库
作为 Obsidian 用户，我希望本 App 不写入 .obsidian/ 等配置目录，以便桌面端配置与插件不受影响。
- Given 我打开并编辑笔记，When App 保存文件，Then .obsidian/ 内容不被修改、不新增文件。
- Given App 需要同步产生的辅助文件，When 落盘位置会进入 vault，Then 先征得我明确同意。
- Given 我浏览文件树，Then 默认不展示 .obsidian/、.trash/、.git/ 等内部目录。

### US-10 外部变更保护
作为多端使用者，我希望文件被外部修改时得到提示而非被静默覆盖。
- Given 笔记被其他设备或桌面端修改，When 我回到 App 或准备保存，
  Then App 提示"文件已变更"，并让我选择重载、保留本地或合并，不静默覆盖任一方。

### US-11 大库可用
作为拥有数千篇笔记的用户，我希望打开、滚动、检索不卡顿。
- Given 一个约 2000 篇笔记的 vault，When 我冷启动并打开，Then 在可接受时间内可阅读，滚动流畅。
- Given 大库，When 我搜索文件名或目录内内容，Then 按需返回结果，不建立常驻索引。

### US-12 数据可控
作为注重隐私的用户，我希望数据只在我的设备与自建节点间传输、密钥不入库、无第三方云。
- Given 同步进行中，When 我查看说明，Then 我能理解中继只转发密文、但会知晓设备 IP 与设备 ID。
- Given 同步凭证与配置，Then 它们只保存在本机安全存储中，不写入 vault、不上传第三方服务。

### US-13 版本历史（本期不实现，仅预留）
作为用户，我希望未来能查看文件历史并回滚误覆盖或误删的内容。
- Given 本期版本，Then 不提供历史查看与回滚功能，但写盘路径与操作记录为未来实现预留接缝。
- Given 未来实现，Then 不得要求用户重新迁移数据或改变现有 vault 结构。

## 2. 非功能需求（可测量）
- NFR-01 前台静置不输入：CPU 均值 < 2%，零网络请求。
- NFR-02 击键主线程耗时 P95 < 8ms；1000 篇库冷启动到可阅读 < 2s。
- NFR-03 息屏/后台非同步期：零定时器、零网络、零文件扫描。
- NFR-04 单次手动同步（100 个变更文件、平均 20KB）在跨网中继下完成；
  峰值内存、耗时、流量需实测记录，同步结束后资源完全释放。
- NFR-05 仅支持 iPad（iPadOS 17+），不做 iPhone / Mac Catalyst。
- NFR-06 分发为个人/企业签名（非 App Store）；后台执行限制与签名方式无关，
  仍不得依赖常驻后台。
